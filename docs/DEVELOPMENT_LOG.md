# Журнал разработки

## 2026-10-23 — этап 08: страница сотрудника на Streamlit

Сделано:

1. Пакет `ui/` — клиент HTTP API без доступа к базе: тест архитектуры
   запрещает ему импорт `app`, SQLAlchemy, psycopg, Alembic, pypdf и FastAPI.
   Streamlit 1.65 вынесен в группу зависимостей `ui`, API от неё не зависит.
2. `ui/client.py` — клиент на `urllib` из стандартной библиотеки: только
   `http`/`https`, экранирование ID в пути, `ApiError` с кодом, сообщением и
   причинами, недоступный сервер — `api_unreachable` без токена.
   Транспорт заменяемый, поэтому тесты ходят во встроенный клиент FastAPI.
3. `ui/keys.py` — `Idempotency-Key` из намерения: хеш действия, процесса,
   версии и значимых входов. Повторная форма, вторая вкладка и
   перезагрузка дают тот же ключ и сохранённый результат.
4. `ui/app.py` — две страницы: список процессов с полями и строками
   источника, сверкой, расхождениями, действиями, черновиком помощника,
   аудитом и outbox; новый счёт — загрузка или текст, извлечение, запуск.
   Кнопки не прячутся по роли и состоянию: отказ показывает сервер,
   `ui/presenters.py` добавляет подсказку к его коду.
5. Два новых маршрута только для чтения: `GET /workflows` (процессы своих
   подразделений, фильтр по состоянию, лимит 1–500) и
   `GET /workflows/{id}/document` (документ, статус извлечения, поля с
   цитатами). Новых таблиц и миграций нет.
6. `python -m app.ui_demo_setup` — вымышленные сотрудники и токены, заказ,
   политика, правила и три образца для проверки страницы.

Проверено в настоящем браузере: вход по токену, загрузка, запуск, сверка,
отказ 403 специалисту, одобрение утверждающим, повторный клик —
`409 invalid_transition`, в базе одно событие outbox; после перезагрузки
токен запрашивается снова.

Исправлено по ходу: `AppTest` не находил страницу по относительному пути;
тест двойного клика ждал повтора из старой вкладки, хотя Streamlit
перезапускает страницу со свежей версией, — теперь он проверяет `409` и
одно событие, а повтор проверяется на форме запуска; тест команды
подготовки вынесен из модуля, который пропускается без Streamlit; первая
сборка PDF вышла на 37 и 36 страниц — описания маршрутов сокращены. Перед
финальным прогоном из `uv.lock` переустановлены `numpy` и `itsdangerous`,
повреждённые синхронизацией iCloud в `.venv`.

PDF-руководства дополнены разделами 28–30 (интерфейс поверх API, повтор и
перезагрузка, ошибки и проверка страницы) с двумя схемами; подсказки к
кодам ошибок читаются из `ui/presenters.py`, отпечаток свежести включает
`ui/**/*.py`. Обе версии — 35 страниц, все 70 просмотрены.

Итог: **493 теста проходят** с PostgreSQL и группой `ui`; без базы — 389
проходят, 104 пропускаются. Коммит и push не выполнялись.

## 2026-10-23 — этап 06: решение сотрудника, роли и outbox

Сделано:

   `view`, `submit`, `reconcile`, `decide`, `Principal` и `authorize`:
   сначала подразделение (чужое — «не найдено»), затем право. Токены

   свежесть функцией этапа 05 и статус `matched`; `approve` и `reject` пишут
   событие outbox, аудит ссылается на снимок и событие. Запись заказа, правил
   и запуск процесса берут те же ключи. Запросы и сверка принимают

   в `app/application/versions.py`, `compute_freshness` — в отдельную функцию.

   добавления), подразделение, автор и снимок решения у процесса, ссылки
   аудита. Существующие процессы получают `unassigned`; это проверено на
   данных, записанных кодом прошлого коммита.
5. HTTP API (`app/api`): зависимость bearer-токена, `Idempotency-Key` с
   префиксом ID сотрудника, строгие схемы, одна форма ошибок, потоковая
   загрузка с лимитом 1 МиБ, 503 без `DATABASE_URL`. Маршруты: `/me`,

   аудит, outbox.
6. `python -m app.users_cli` и `python -m app.decisions_demo`; демонстрации
   этапов 03–05 регистрируют вымышленного согласующего для своих решений.

Исправлено по ходу: запуск в чужом подразделении сначала отвечал «не
найдено» про процесс — теперь `missing_permission`, ведь подразделение
называет сам вызывающий. Тест истории для `outbox_events` не находил ошибку

После перезапуска приложения каталог временных файлов очистился, и
временный кластер PostgreSQL создан заново; все проверки выполнены на нём.

## 2026-10-23 — этап 03: PostgreSQL, транзакции, аудит и идемпотентность

Добавлены зависимости SQLAlchemy 2.1.4, Alembic 1.20.0 и psycopg 3.3.6
(с отсечкой разрешения `2026-10-09`, как и раньше). Настройка `DATABASE_URL`
хранится как `SecretStr`; тестовая фикстура удаляет её из окружения вместе
с переменными `APP_*`.

Структура слоёв:

1. `app/domain/content_hash.py` — канонический JSON и SHA-256 для счёта,
   заказа и политики. Модуль использует только стандартную библиотеку.
2. `app/application/` — `WorkflowService`, записи (`VersionRef`,
   `StoredWorkflow`, `ValidationSnapshot`, `AuditEvent`…), протоколы
   `WorkflowRepository`/`UnitOfWork` и коды ошибок. SQLAlchemy здесь не
   импортируется; это проверяет новый тест границ импорта.
3. `app/infrastructure/db/` — модели девяти таблиц с `NUMERIC(14,2)` для
   денег, `NUMERIC(12,6)` для количества и именованными `CHECK`, репозиторий
   с проверкой хешей при чтении, unit of work, движок с таймаутами и защита
   тестовой базы по суффиксу `_test`.
4. `migrations/` — Alembic. Ревизия `0001` сгенерирована автоматически и
   исправлена вручную: циклическая ссылка процесса на снимок добавляется после
   создания обеих таблиц, таблицы истории получают триггер против `UPDATE` и
   `DELETE`.

Команды `start`, `check`, `approve`, `reject`, `revise` выполняются в одной
транзакции: запись ключа идемпотентности, снимок проверки, условное обновление
версии процесса и событие аудита. Процесс закрепляет конкретные версии входов;
новая версия заказа не меняет прежние снимки. Повтор с тем же ключом возвращает
исходный результат, другой запрос с тем же ключом отклоняется, неудачная
команда ключ не расходует.

## 2026-10-23 — этап 02: предметная модель и базовый процесс

Добавлен чистый Python-домен в `app/domain/`. Неизменяемые модели описывают
деньги, позицию, счёт и заказ на закупку. Обязательные поля, валюты, количество
и итоги проверяются при создании; ошибочный заявленный итог счёта сохраняется
как вход для правил, чтобы расхождение оставалось обнаружимым.

Деньги принимают только `Decimal`. Для вымышленных USD, EUR и UZS действует
явная политика двух десятичных знаков. Округление HALF_UP выполняется один раз
для каждой позиции, затем складываются округлённые итоги. Частный десятичный
контекст защищает результат от настроек вызывающего кода; переполнение
отклоняется.

Реализованы семь кодов базовой проверки, входной снимок результата и состояния
`received`, `needs_review`, `awaiting_approval`, `approved`, `rejected`.
Команды проверки, одобрения, отклонения и исправления возвращают новые объекты.
Правка снимает предыдущую проверку; конечные состояния блокируют новые команды.
Одобрение требует чистого актуального результата и отдельного решения с
идентификатором и причиной. Это метаданные демонстрации, не аутентификация.

Команда `uv run --locked python -m app.demo` печатает три вымышленных сценария:
счёт на 30 USD с явным решением, неверный итог 31 USD и отсутствие заказа.
Программа не пишет файлы, не вызывает сеть и не загружает настройки веб-сервиса.

Добавлены [русское руководство](STAGE_02.md),
[короткая инструкция](instructions/domain.md) и
[ADR 0002](adr/0002-domain-rules-and-workflow.md). Обновлены README,
дорожная карта, структура, инструкции и сводка проверки. Пакеты `tests` и
`tests/domain` получили `__init__.py`, чтобы mypy различал вложенные `conftest`.

Тесты включают независимые ожидаемые суммы, запрещённые переходы, устаревшие
снимки и запуск CLI без сторонних пакетов. Точные команды и границы приведены

## 2026-10-23 — этап 01: начало проекта
