### Временный PostgreSQL

Использован PostgreSQL **18.3** из Homebrew. Сервис пользователя не
запускался и не настраивался: создан отдельный кластер командой `initdb`
в каталоге временных файлов сессии и запущен через `pg_ctl` только на
`127.0.0.1:55433`, без Unix-сокета, с проверкой пароля `scram-sha-256`.
Для запуска потребовалась переменная `LC_ALL=C`: без неё сервер Homebrew
останавливался при старте с сообщением о многопоточности.

В кластере созданы роль `enterprise_workflow`, база разработки
`enterprise_workflow` и тестовая база `enterprise_workflow_test`. Пароль
локальной одноразовой роли в репозиторий не записывался.

## Тесты этапа 03

Добавлено 70 тестов; 142 теста этапов 01–02 сохраняются и проходят.

Без базы данных (34):

- **7 тестов хеша содержимого:** ожидаемый SHA-256 вычисляется от вручную
  записанного канонического JSON, а не через рабочую функцию; порядок валют,
  нормализация `Decimal`, изменение полей, UTF-8.
- **9 тестов адреса БД:** только `postgresql+psycopg://`, имя базы обязательно,
  тестовая база должна оканчиваться на `_test`, пароль не попадает в ошибки.
- **14 тестов аргументов команд:** неверные контекст, версия (`0`, `True`,
  `"1"`, `1.0`), решение, идентификаторы и документы отклоняются до открытия
  транзакции — фабрика unit of work в этих тестах падает при вызове.
- **2 теста границ импорта:** `app/domain` и `app/application` не импортируют
  FastAPI, Pydantic, SQLAlchemy, Alembic и psycopg.
- **1 тест настроек:** `DATABASE_URL` читается, пароль скрыт в `repr` и дампе.
- **1 тест CLI:** без `DATABASE_URL` демонстрация завершается с кодом 2 без
  трассировки стека.

С PostgreSQL (36):

- **12 тестов схемы:** откат и повторное применение миграции, совпадение схемы
  с моделями через `compare_metadata`, типы `numeric(14,2)` и `numeric(12,6)`,
  чтение суммы как `Decimal`, отказ `UPDATE`/`DELETE` для каждой из восьми
  таблиц истории, отказ `CHECK` для валюты `GBP`.
- **6 тестов версий:** повтор того же содержимого, A → B → A = версии 1, 2, 3,
  точность `0.333333 × 999999.99`, порядок валют политики, обнаружение строки,
  изменённой при отключённом триггере, одновременная запись одной новой версии
  четырьмя потоками.
- **12 тестов команд:** аудит `start`, путь `start → check → approve`, чтение
  новым пулом соединений, коды причин в аудите без текста позиций, повтор
  без новых строк, повторное использование ключа, устаревшая версия, ошибка
  домена не расходует ключ, повторный `start` и отсутствующие версии,
  откат всей транзакции при сбое записи аудита, сохранность старого снимка
  после новых версий заказа и политики, ссылка на снимок после `reject`.
- **4 теста конкурентности:** одновременные дубликаты выполняются один раз,
  из двух разных команд по одной версии выигрывает одна, условный `UPDATE`
  блокирует потерянное обновление, детерминированная гонка «ключ не найден →
  дубликат зафиксирован → прочитана версия 2» отвечает повтором.
- **2 теста демонстрации:** ожидаемые шаги и снимки; `run` и `show` в отдельных
  процессах Python дают одинаковое сохранённое состояние.

Ожидаемые значения заданы независимо: например, итог позиции
`999999.99 × 0.333333 = 333332.99666667` округлён вручную до `333333.00`.

### Найденная гонка и повторяемость

До исправления многопоточный тест одновременных дубликатов упал в 8 из 10
повторных запусков: второй запрос получал `version_conflict` вместо повтора.
После исправления детерминированный тест этого порядка событий падает при
отключённом исправлении и проходит при включённом. Затем 30 повторных запусков
`tests/persistence/test_concurrency.py` и 15 запусков вместе с
`test_versions.py` завершились без ошибок. Это снижает, но не исключает
вероятность других редких гонок.

## Границы результата

- GitHub Actions: **`not_verified`**. В workflow добавлены сервис
  `postgres:18.3` по digest, шаги Alembic и `REQUIRE_TEST_DATABASE=1`;
  удалённый запуск не выполнялся. Коммит и push не выполнялись.

  `docker buildx imagetools inspect postgres:18.3`. Пример `docker run`
  в руководстве не проверялся. Linux и Windows отдельно не проверялись.

- `actor_id` и `source` заявляются вызывающим кодом; аутентификации и ролей нет.

  устаревшим и не запрещает одобрение: это этапы 05 и 06.

- Триггеры защищают историю от случайных правок, но владелец базы может их
  отключить. Резервного копирования и политики хранения нет.

  на этапе 04. Реальная LLM и корпоративные системы не вызывались.
