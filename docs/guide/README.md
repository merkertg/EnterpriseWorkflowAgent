Руководство есть в двух одинаковых по структуре версиях:

- [enterprise-workflow-agent-guide.pdf](enterprise-workflow-agent-guide.pdf) — на русском;
- [enterprise-workflow-agent-guide-en.pdf](enterprise-workflow-agent-guide-en.pdf) — на английском.

В каждой версии 29 страниц: обложка и 28 разделов. Раздел 1 — проект за
минуту и дорожная карта. Разделы 2–3 относятся к этапу 01: окружение, запуск,
настройки, проверки и CI. Разделы 4–6 — к этапу 02: деньги и документы,
базовые правила, состояния процесса. Разделы 7–12 — к этапу 03: слои и порты,
таблицы и миграции, версии и хеши, транзакция команды, блокировка и повтор,
аудит и снимки. Разделы 13–17 — к этапу 04: приём документа, PDF в отдельном
процессе, поля и цитаты, проверка извлечения, хранение и командная строка.
Разделы 18–20 — к этапу 05: правила сверки, сверка строк, снимок и
устаревание. Разделы 21–24 — к этапу 06: вход и роли, одобрение по свежей
сверке, HTTP API, outbox и аудит решения. Разделы 25–28 общие: шпаргалка
команд, типичные ошибки, вопросы для самопроверки и итоги проверки.

Markdown-руководства этапов остаются подробным источником объяснений. PDF —
их наглядная сводка со схемами; при изменении этапа обновляются оба.

## Какие файлы составляют руководство

| Файл | Назначение |
| --- | --- |
| [enterprise-workflow-agent-guide.pdf](enterprise-workflow-agent-guide.pdf), [enterprise-workflow-agent-guide-en.pdf](enterprise-workflow-agent-guide-en.pdf) | Итоговые документы для чтения и показа |
| [verification.json](verification.json) | Фактические результаты проверки: дата, коммит, тесты, команды, статус удалённого CI |
| [../../scripts/build_guide.py](../../scripts/build_guide.py) | Точка входа: обложка, колонтитулы, проверка JSON, сборка обеих версий |
| [../../scripts/guide/](../../scripts/guide/) | `i18n.py` (язык и `tr()`), `layout.py` (шрифты, стили, блоки), `diagrams.py` (схемы), `sources.py` (данные проекта), `toc.py` (оглавление), `stage01_02.py`, `stage03.py`, `stage04.py`, `stage05.py`, `stage06.py`, `story.py` (тексты разделов), `fingerprint.py` (отпечаток исходников) |
| [../../tests/test_guide_pdfs.py](../../tests/test_guide_pdfs.py) | Проверка свежести и содержания обоих PDF |

Каждый текст задаётся парой `tr("русский", "english")`, поэтому обе версии
имеют одинаковую структуру. Разделы находятся по русскому заголовку
(`section(story, "Итоги проверки", ...)`), а не по номеру: новый раздел
сдвигает нумерацию автоматически.

Часть данных генератор читает прямо из проекта, а не из текста:

- версии пакетов и их число — из `uv.lock`, версия Python — из `.python-version`;
- коды проверок, состояния, команды, коды отказа, проблем и расхождений,
  статусы полей, причины устаревания, версия логики сверки, роли и права,
  типы событий outbox — из перечислений `app/domain` и `app/application`;
- деловые маршруты HTTP — из роутера `app/api/routes/business.py`, а
  соответствие кодов ошибок статусам — из `ERROR_STATUS` в `app/api/errors.py`;
- лимиты документов — из `DocumentLimits()`;
- список таблиц и таблиц только для добавления — из моделей SQLAlchemy;
- список миграций — из `migrations/versions/`;
- отрывки кода (`/health`, `Money.multiply`, `update_workflow`,
  `read_pages`) — из исходных файлов через `ast`;
- числа тестов, команды и статус CI — из `verification.json`.

Если в базе появится таблица без описания в `stage03.py` или маршрут без
описания в `stage06.py`, сборка остановится с ошибкой, а не выпустит
неполный PDF.

## Как пересобрать

ReportLab 4.4.9 закреплён в отдельной группе зависимостей `guide` в
`pyproject.toml` и `uv.lock`; в рабочие зависимости приложения он не входит.
Запуск из корня проекта:

```bash
uv run --locked --group guide python scripts/build_guide.py
```

По умолчанию собираются обе версии. Одна версия:

```bash
uv run --locked --group guide python scripts/build_guide.py --lang en
```

`--output` задаёт другой путь и работает только с `--lang ru` или `--lang en`.

На macOS используются системные шрифты PT Sans и PT Mono из
`/System/Library/Fonts/Supplemental/`, на Linux — DejaVu Sans
(`fonts-dejavu-core`). Если шрифтов нет, сборка останавливается с ошибкой.
В PT Sans нет стрелок `→ ← ↓ ↑`: функции `p()` и `draw_text()` рисуют их
шрифтом PT Mono. Символы `✓` и `✗` не поддерживаются ни одним из двух
шрифтов PT — их не используем.

Старый PDF перед сборкой копируется во временный каталог системы
(`<имя>-before-<дата-время>.pdf`). Новый файл собирается рядом во временный
и заменяет PDF только после успешной сборки.

## Почему PDF не может устареть незаметно

Сборка записывает в поле Keywords каждого PDF строку
`source-sha256:<хеш>`. Хеш вычисляет `scripts/guide/fingerprint.py` от путей
и содержимого файлов генератора, `verification.json`, `uv.lock`, всего кода
`app/` и ревизий `migrations/versions/`. Тест `tests/test_guide_pdfs.py`
вычисляет хеш заново: если что-то из этого изменилось, а PDF не пересобраны,
тест падает с подсказкой команды пересборки. Тот же тест проверяет, что
в каждой версии есть заголовки всех разделов, в английской нет кириллицы,
а в русской она есть. Для теста ReportLab не нужен, он работает и в CI.

Тест подтверждает, что PDF собран из текущих исходников. Качество вёрстки
он не подтверждает — для этого нужна визуальная проверка ниже.

## Как обновлять

1. Выполни проверки по [инструкции тестирования](../instructions/testing.md).
2. Запиши фактические результаты в `verification.json`: дату, коммит, блок
   `tests`, команды и статус CI. Генератор отклонит JSON, где
   `passed + failed + skipped ≠ total` или пропущенные без базы не равны
   числу тестов PostgreSQL.
3. Если изменился этап, обнови тексты разделов в `scripts/guide/` на обоих
   языках и при необходимости добавь раздел в `toc.py`.
4. Пересобери обе версии и проверь каждую страницу.
5. Зафиксируй исходники, JSON и оба PDF одним коммитом.

## Как проверить PDF после сборки

```bash
pdfinfo docs/guide/enterprise-workflow-agent-guide.pdf
pdftoppm -r 70 -png docs/guide/enterprise-workflow-agent-guide.pdf /tmp/ewa-guide/ru
pdftoppm -r 70 -png docs/guide/enterprise-workflow-agent-guide-en.pdf /tmp/ewa-guide/en
```

Создай каталог `/tmp/ewa-guide` заранее. `pdfinfo` и `pdftoppm` входят в
Poppler (`brew install poppler`). Проверь каждую страницу обеих версий:
кириллица и стрелки читаются, нет пустых квадратиков, код и таблицы
помещаются в поля, подписи схем не лежат на линиях и не пересекаются,
заголовок не остаётся один внизу страницы. Сверь числа тестов и статус CI
с `verification.json`.
